# Agent Workflows

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users and purpose

Developers operating local durable coding workflows inspect Runs, recorded
evidence, and Executions, then issue explicit operator commands. The browser
monitor carries forward the terminal monitor's priorities: stable selection,
clear attention states, and evidence before technical detail.

## Operating context

The operator starts `run` on a local machine and opens its printed access URL.
The web monitor is optional, local-only, and independent of workflow execution.
The terminal monitor remains available. Existing Node and PostgreSQL prerequisites
remain; no extra installation or service setup is required.

## Capabilities and constraints

Inspect projects, Runs, activity, validation, Executions, diagnostics, agent
sessions, and local logs. Pause, resume, stop, retry, retry with a refreshed issue,
recover publication, and reload configuration through existing command policy.
Readiness and delivery are distinct. Missing evidence must not appear successful.
Browser notifications and remote access are outside scope.

## Product principles

- Explain the selected subject and need for intervention before technical detail.
- Preserve selection during updates and distinguish stale data from live state.
- Distinguish submitted commands from acknowledged outcomes.
- Closing a monitor never stops workflows.

## Evidence on hand

The terminal design, monitor scenario fixtures, and accepted ADR 0008 establish
behavior. Preview data must be labelled as fixtures; production displays only
recorded evidence.
